---
name: check
description: Check a change against its approved RBB spec and plan, show the review, and ask for a verdict on each difference the check found - accept it as an amendment, dispute it before an independent judge, or have the builder rework it. The check runs as a workflow that never sees the builder's conversation, and writes .rbb/<change>/check.json and the review page, review.md.
argument-hint: <change> [grouped|per-hunk] [rework|verdicts]
---

Arguments: $ARGUMENTS

The first word is the change. A word `grouped` or `per-hunk` is the mode (grouped when absent). The word `rework` asks for every difference to be reworked until the check is clean, with no question. The word `verdicts` skips the check and asks for verdicts on the differences of the last check.

1. If `.rbb/config.json` does not exist, the repository is not set up: invoke the skill `rbb:setup` with the Skill tool and no argument first, and stop if it reported an error.
2. Unless the arguments hold `verdicts`: run the plugin workflow `rbb:check-change` with the Workflow tool, with args `{"change": "<change>", "mode": "<mode>"}`. Do not write any file yourself. If it returned an error, show it as written and stop. When it finishes, show the requester `.rbb/<change>/review.md` exactly as written. Add nothing of your own: no summary, no judgement of the result, no advice. If the result says `review_recorded` is false, say instead that the review page could not be saved and that `.rbb/<change>/check.json` holds the result. If its `differences` is empty, end with the next step, one line: `/rbb:pr <change>` writes the pull request body; and stop.
3. If the arguments hold `rework`: say in one sentence that the builder will rework every difference until the check is clean, up to three rounds in all, and that a confirmation may appear for removing files its runs leave behind. Run the plugin workflow `rbb:settle-differences` with args `{"change": "<change>", "verdicts": [], "until_clean": true}` and wait, then go to step 7.
4. If the arguments hold `verdicts`: run `rbb:settle-differences` with args `{"change": "<change>"}`; it changes nothing and returns the open `differences`. If it returned an error, show it as written and stop. If `differences` is empty, say that the last check has no open difference, and stop.
5. Ask with `AskUserQuestion`, one question: "The check found <count> difference(s) from the approved spec. How do you want to handle them?" with the options "Decide each one" (described: accept, dispute or rework each difference, one answer each), "Rework every difference until the check is clean" (described: the builder is sent back with all of them and the check runs again, repeated up to `rework_left` more rounds; leave this option out when `rework_left` is 0) and "Leave them as they are" (described: the review and the pull request show them as open differences). On "Leave them as they are", end with the next step, one line: `/rbb:check <change> verdicts` answers them later, and `/rbb:pr <change>` writes the pull request body with them open; and stop. On "Rework every difference until the check is clean", say the sentence of step 3, run `rbb:settle-differences` with args `{"change": "<change>", "verdicts": [], "until_clean": true}`, wait, and go to step 7.
6. On "Decide each one": for each entry of `differences`, in order, in `AskUserQuestion` calls of at most four questions each, ask "Difference <n>: <its text as written>" with the options "Accept" (described: it becomes part of the approved change, as an amendment in your words, frozen like the approval), "Dispute" (described: an independent judge re-examines the finding with your rebuttal and upholds or withdraws it) and "Rework" (described: the builder is sent back to resolve it and the check runs again). Then, for each difference accepted or disputed, ask for the requester's words, again at most four questions per call: for an accepted one, "Difference <n>, accepted. In your words, what does the change rightly include here?" with the options "As the review states it" and "The code is right as it is"; for a disputed one, "Difference <n>, disputed. Why is the check wrong here?" with the options "The change does what the spec asks at this place" and "The spec, as approved, allows this". Words the requester types under Other are taken exactly as written; a chosen option is its label as written. If any verdict is rework, say the sentence of step 3. Then run `rbb:settle-differences` with args `{"change": "<change>", "verdicts": [{"difference": <n>, "verdict": "accept" | "dispute" | "rework", "words": "<the words>"}, ...]}`, one entry per difference answered, and wait.
7. When it finishes: if it returned an error, show it as written and stop. Show `.rbb/<change>/review.md` again, exactly as written. Then say, one line each and only those that apply: each amendment by its words (`amendments`); each withdrawn dispute with the judge's reason (`withdrawn`); each upheld dispute with the judge's reason (`upheld`); each rework round with its commit and the verdict of the check that followed (`rework_rounds`); and `rework_stopped` or `rework_error` as written. If `differences` is not empty and `rework_stopped` is absent, go back to step 5 with them; "Leave them as they are" ends it. Otherwise end with the next step, one line: `/rbb:pr <change>` writes the pull request body. Whenever a step above shows an error, also say that `/rbb:check <change>` runs the check again once the cause is fixed.
